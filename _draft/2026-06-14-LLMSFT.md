SFT(Supervised Fine-Tuning) 和预训练一样，都是在学习：给定前面的 token，预测下一个 token。而 SFT 阶段更多地把预训练模型的概率分布重新往目标行为偏移。

在完成预训练时，模型具备强大的语言理解和生成能力，但还只是一个无情 Next-Token Prediction 机器，不理解问答或指令遵从的范式；有监督的问答序列数据训练，
让模型理解以指令遵从和对话的方式安心当一只美国大豆包或者橙色章鱼，此时模型被 align 到助手的角色，之后也许会有偏好对齐阶段再进一步优化人类更喜欢哪个回答。但总之，SFT 是实践起来成本最低而且收益最直接的一步。

# 1. SFT 流程包含什么

刚好最近在教实习生使用训练框架和调度集群，来大致记录一下训练全流程。

1. 数据准备与 Chat Template 格式化：对初始语料有一个筛选过程，可能会基于规则（长度、乱码率）/基于模型（困惑度打分），去掉重复、格式混乱、含偏见等数据；然后将原始的指令和回答拼接成含Special Tokens 的 Chat Template。根据 LIMA 等研究，几千到上万条高质量、多样化的专家编写数据，其效果往往优于数十万条低质量或机器自动生成的嘈杂数据。数据处理阶段需要考虑的最重要内容就是**训推一致**，要求训练和推理阶段的 Chat Template 格式要完全一致，即使是多了一个空格或换行符，也可能导致推理时模型输出异常、重复或拒绝回答。一般来说统一使用 Hugging Face 的 `tokenizer.apply_chat_template`作为加工的基础会比较合理。
2. 标签掩码（Label Masking）：在计算 Loss 时，只对模型的 Response 部分计算 Loss，而对输入的 Prompt 进行 mask（torch 中 label 设为 -100），避免模型去预测输入本身。
3. 动态填充与 Batch 组装：在同一个 Batch 内对不同长度的文本进行 Padding，并设置相应的 attention_mask。
4. 模型配置与加载：根据模板训练框架的格式、并行度转换模型权重，然后加载；可能会引入 PEFT（如 LoRA）以节省显存。
5. 训练与分布式加速：通过自回归（Autoregressive）方式计算交叉熵损失，并更新模型参数，执行前向传播与反向传播循环。
6. 评测：把模型权重转化为部署需要的格式，按需评测。

对不同的训练框架，上述数据处理过程可能包含格式的转换。当使用 Megatron 的框架时，需要确保模型和权重都以 Megatron 格式处理。

> MindSpeed 并没有完全重写一套 Megatron，而是用 Monkey Patch 在运行时动态地拦截 Megatron-LM 的底层调用，将其中的 GPU 特有算子、CUDA 相关的通信组件等，无缝替换为适配昇腾 NPU、CANN 以及 HCCL 的高性能算子。因为类似的原因，MindSpeed 也支持 FSDP 推理后端。如果使用 Megatron，就需要把模型和数据都转为 Megatron 的专有格式，来适配并行各种模型切分

从数学上看, SFT （仍然）在做：$\max_{\theta}\sum \log P_{\theta}(y_t|x,y_{\lt t})$，其中：$x$ 是 Prompt，$y$ 是 Response。

# 2. SFT 如何改变模型行为

SFT 的优化目标可以说是在 **给定指令（Prompt）的条件下，最大化模型输出期望回答（Response）的条件概率。** 大量问答对样本累计后，对应回答 token 出现概率提升，导致整个回答风格发生迁移。

因此，SFT 的本质是**对条件概率分布进行局部重塑**。

在机器学习的框架下，这通常通过最小化 *目标文本*（Response）的负对数似然（Negative Log-Likelihood, NLL）来实现，训练过程采用的是**Teacher Forcing**模式，即永远喂真实历史（Ground Truth），而非模型在上一步实际预测出的 Token。

下文公式中的条件项 $y_{<i}$ 就对应的 Ground Truth，而不是之前模型采样/贪心解码的 Token - 这意味着在训练迭代中，即使模型在第 $i-1$ 步预测错了，在第 $i$ 步时我们依然输入正确的 $y_{i-1}$ 来引导模型预测 $y_i$。这保证了训练的**并行性**（Teacher Forcing 使得全部输入前缀在训练时已知，再借助 Transformer 的因果掩码，才能一次性并行计算整条序列的 loss）。

Teacher Forcing 带来的经典问题是 Exposure Bias：模型永远只见过正确前缀这种输入分布。而模型必须基于自己生成的 token 继续往下生成。一旦某步出错，错误 token 会进入后续的条件输入，且这种前缀在训练时从未出现过，误差会逐步累积、放大，导致训练和推理分布不一致 $P_{train}\neq P_{infer}$ ，即 **Exposure Bias**。

> 这也是后来 RLHF、DPO、RFT(Reinforcement Fine-Tuning, not Rejection Sampling Fine-Tuning) 出现的重要原因之一。不过近年也有工作（如 Schmidt 2019 等）质疑 Exposure Bias 在实践中的实际危害被高估，认为很多所谓"暴露偏差"的现象也可归因于模型分布覆盖不足。可以把它当作一个重要的理论动机，但不必视为绝对定论。

> RLHF: 模型训练时喂给自己的输入，就是自己一步步预测出来的 Token 历史（$P_{train} = P_{infer}$)
> 剩下的方法也是 On-policy Ways, like Online DPO or Reinforcement Fine-Tuning: 动态迭代的方式将 DPO 变成了 On-Policy 训练，在模型自己生成的完整序列上做序列级优化，而非在固定的真实前缀上做逐 token 的模仿学习，那肯定彻底对齐了训练和推理的分布。

> 另外：
> 
> - Scheduled Sampling（Bengio et al., 2015）：训练时以一定概率用模型自己的预测替代 Ground Truth，概率随训练逐渐提高，缩小训练/推理差距
> - Professor Forcing：用对抗训练让"teacher-forced 隐状态"和"自由生成隐状态"分布对齐
> - 序列级训练 / 最小风险训练（MIXER、MRT、RAML 等）：直接优化序列级指标（如 BLEU），在模型自己生成的序列上计算目标

# 3. 原理与实现

来点数学。

我们定义：

* 设输入指令 Prompt 序列为：$x = (x_1, x_2, \dots, x_M)$，长度为 $M$。
* 设期望的目标回答 Response 序列为：$y = (y_1, y_2, \dots, y_N)$，长度为 $N$。
* 设模型的参数为 $\theta$。

### 单个样本的损失函数 / Single Sample Loss

前面提到，SFT 的优化目标是最小化 NLL，对于单个样本 $(x, y)$，其损失函数定义为：

$$
\mathcal{L}(\theta; x, y) = -\log P_\theta(y | x) = -\sum_{i=1}^{N} \log P_\theta(y_i | x, y_{<i})
$$

而自回归语言模型生成回答 $y$ 的过程是逐个 Token 进行的。在给定输入 $x$ 的情况下，生成完整回答 $y$ 的联合条件概率可分解为各个步骤条件概率的乘积（乘积的对数 = 对数的求和嘛）：

$$
P_\theta(y | x) = \prod_{i=1}^{N} P_\theta(y_i | x, y_{<i})
$$

其中 $y_{<i} = (y_1, y_2, \dots, y_{i-1})$ 表示在第 $i$ 步之前已经生成的所有目标 Token。

> 为什么取对数？1. 避免连乘下溢（求和数值稳定）； 2. 求导更简单（和的导数=导数的和，反向传播天然按 token 累加梯度）；3. 与信息论/交叉熵一致（−logP 就是编码所需的比特/nats）。

**工程内涵：**在具体的多分类实现中，单步的概率 $P_\theta(y_i | x, y_{<i})$ 是通过对模型输出的 Logits 进行 Softmax 变换得到的。因此，上述最大似然估计 $P_\theta$ 的值工程上完全等价于计算预测 Logits 与真实 One-Hot 标签之间的**交叉熵损失**（Logit Softmax 后对应 token 位置的概率值）。

### 数据集上的总体优化目标 / Dataset Optimization Objective

设 SFT 训练数据集为 $\mathcal{D} = \{(x^{(k)}, y^{(k)})\}_{k=1}^{|\mathcal{D}|}$。SFT 的最终优化目标是寻找一组参数 $\theta^*$，使得在整个数据集上的**平均损失**最小：

$$
\theta^* = \arg\min_\theta \mathcal{L}_{\text{SFT}}(\theta)
$$

$$
\mathcal{L}_{\text{SFT}}(\theta) = -\frac{1}{|\mathcal{D}|} \sum_{k=1}^{|\mathcal{D}|} \sum_{i=1}^{N_k} \log P_\theta(y_i^{(k)} | x^{(k)}, y_{<i}^{(k)})
$$

其中 $N_k$ 是第 $k$ 个样本中回答 $y^{(k)}$ 的长度。

### 与预训练阶段的区别

预训练阶段不对输入和输出做区分（无条件自回归），对整个文本序列 $S = (s_1, s_2, \dots, s_L)$ 的所有 Token 都计算损失：

$$
\mathcal{L}_{\text{Pretrain}}(\theta) = -\sum_{t=1}^{L} \log P_\theta(s_t | s_{<t})
$$

在 SFT 中，我们将输入 $x$ 和输出 $y$ 拼接成一个完整的序列 $U = [x; y] = (u_1, u_2, \dots, u_{M+N})$。
而且只对回答部分 $y$ 计算梯度（loss），为此我们引入一个**掩码权重 $w_j$**：

$$
w_j = \begin{cases} 0, & \text{if } u_j \in x \text{ (prompt)} \\ 1, & \text{若 } u_j \in y \text{ (response)} \end{cases}
$$

结合掩码后，SFT 的损失函数在代码实现层面表现为：

$$
\mathcal{L}_{\text{SFT\_Masked}}(\theta) = -\sum_{j=1}^{M+N} w_j \log P_\theta(u_j | u_{<j})
$$

在实际的 PyTorch 代码中，这正是通过将 $w_j = 0$ 对应位置的 Label 设为 `-100`，从而在 `CrossEntropyLoss(ignore_index=-100)` 中将该部分的损失项权重设为 0 来实现。

通常情况下，我们不会计算 User/System/Observation 部分的 loss，他们的Label会被打成 -100。否则模型会尝试学习用户输入的内容，属于一种无意义推测了。

另外，User部分 mask，Assistant部分 unmask 被称为 Completion-Only SFT。现代模型会用 Special Token 把他们分割好，在训练框架中处理。对 Agent 轨迹，尤其是非主流输出的内容，得自己把 Thought, Action 等相应标记好算 loss, observation 不算。我最近实现的有趣算法里对 loss 计算做了选择性的 mask,投稿了一篇文章。如果它未来中了会在这里标出来。作为工作最后一阶段和 Dual、YY 一起留下的回忆，希望可以有机会让我写更多东西。

# 4. SFT 的问题

这里包含 SFT 本身的瓶颈、限制和可能会碰到的问题。就都写在这里吧！

## 长序列SFT的特殊问题

对于Agent轨迹，有一个 Loss Dilution 的问题，即历史记录可能很长，但loss取平均：$L=\frac1N\sum l_t$，
则 Final Answer 部分梯度被稀释。

一个常见做法是 **加权Loss**，$L=\sum w_t l_t$，可以给 Thought，Action，Final Answer 不同权重。此时可以提高最终答案权重。

## Packing

拼接多条数据一次训练，提高GPU利用率。

背景是不同的对话样本长度差异很大。如果简单地将它们 Padding（填充）到最大长度（如 4096），会导致显存中存在大量的 Padding Token（如 `<pad>`），浪费计算资源。

* **解决方案：**
  * 采用 **Packing** 技术，将多个短样本拼接成一条达到最大长度（如 4096）的长样本，中间用 EOS（End of Sequence）Token 隔开。
  * 在注意力计算时，需要配合 **Block Diagonal Attention（块对角注意力）**，防止样本 A 的输入关注到同一个拼接序列中样本 B 的内容。主流框架如 Hugging Face TRL 库中的 `SFTTrainer` 提供了 `packing=True` 选项。

## Loss Spike

Spike 的成因可能来自于某个特定 batch 里的脏数据（比如无意义重复字符、label 全空啥的），经过 attention 机制计算会产生极大注意力权重。

还有一种可能，如果 MoE 模型专家数量很多的时候，路由网络（Router）计算出的 logits 会进行 softmax，如果此时路由计算在 BF16 / FP16 这种低精度场景下进行，容易发生数值溢出或下溢，导致分配给某些专家的权重瞬间失衡，引发梯度爆炸和 loss spike。这种的话添加一个 `--moe-router-dtype fp32` 强制使用 FP32 精度计算路由模块就可以了。

同时， MoE 训练过程中的 Router 层 logits 可能会随着训练进行不断变大，导致 softmax 计算不稳定。这种情况可以引入 Z-loss 惩罚项（`--moe-z-loss-coeff 1e-5`，让 router 倾向于输出绝对值较小的 logits）来提升大规模专家训练时的稳定性。

更通用的解决方法是**学习率**相关的。一般来说，训练初期的 Spike 可以开 warmup （`--lr-warmup-iters 200`，通常设为总步数的1%~5%）来提供 LR 的缓冲阶段来缓解，缓冲阶段会让 LR 从极小值开始在指定步数内线性增加到最大学习率。但是训练中后期出现的 Spike 设置 warmup 是完全没用的。

在全局角度还可以设置梯度裁剪（`--clip-grad 1.0`）来限制梯度增大时的模长在一个安全范围内；或者适当降低最大学习率。

## What about LoRA-SFT

LoRA（Low-Rank Adaptation，低秩适配）是一种参数高效微调（PEFT, Parameter-Efficient Fine-Tuning） 方法。
核心就是：不直接修改大模型原本的权重，而是在某些权重旁边增加一组很小的、低秩的可训练参数，只训练这些参数。

和全参数SFT相比，LoRA的目标(都是最小化带掩码的 NLL)、损失、数据（loss masking）、训练范式（Teacher Forceing）完全相同，唯一的区别在于**更新哪些参数、怎么更新**：
全参 SFT 更新全部权重（效果上限高、成本高、易遗忘），
LoRA-SFT 冻结主干只训练低秩旁路（省显存、可热插拔、抗遗忘，但表达力受秩约束）。

工程上从全参切到 LoRA，基本只是多包一层 PEFT + 调大学习率而已。

### 1. 全参 SFT

直接更新所有权重：

$$
W \leftarrow W - \eta \,\nabla_W \mathcal{L},\qquad W\in\mathbb{R}^{d\times k}\ \text{全部可训练}
$$

### 2. LoRA-SFT

**冻结**原权重 $W_0$，只训练一个低秩增量：

$$
W = W_0 + \Delta W = W_0 + \tfrac{\alpha}{r} BA,\qquad B\in\mathbb{R}^{d\times r},\ A\in\mathbb{R}^{r\times k},\ r\ll\min(d,k)
$$

前向：$h = W_0 x + \tfrac{\alpha}{r}B(Ax)$。$A$ 高斯初始化、$B$ 置零，保证起点 $\Delta W=0$ 不破坏预训练权重。**梯度只流向 $A,B$**，$W_0$ 不动。

这里的 $r$：LoRA rank，通常远小于 $d,k$
$\alpha$：LoRA scaling
$A,B$：可训练参数

可训练参数量从 $dk$ 降到 $r(d+k)$，通常只占全模型的 **0.1%~1%**。

这样让 **显存**（以 Adam、混合精度为例）开销明显下降：

> - 全参 SFT 每个可训练参数需存：权重 + 梯度 + Adam 的一阶/二阶动量 ≈ **权重的 4 倍附加开销**。7B 全参微调常需 60~80GB+。

> - LoRA 只有 $A,B$ 需要梯度和优化器状态，$W_0$ 只读（甚至可量化成 4-bit → **QLoRA**）。7B QLoRA 单张 24GB 卡即可。

其次因为 LoRA 冻结了基座模型的权重，无论 LoRA 参数如何剧烈变化，原始的预训练知识都不会被直接破坏（不会灾难性遗忘）。因此，可以使用更大的学习率来加速旁路参数的收敛。全参数SFT的学习率 1e-5 ~ 2e-5，但是LoRA可以到 1e-4 ~ 3e-4（高 10 倍左右）。

LoRA 产出的 adapter 只有几十~几百 MB，可**热插拔**、一个底座挂多个 adapter 服务不同任务；推理时也可**合并**回主干（$W\leftarrow W_0+\tfrac{\alpha}{r}BA$）实现零额外延迟。

> Adapter 本质上就是这两个低秩矩阵 A 和 B 的权重集合。它存储的不是模型本身，而是模型权重的变化量的低维投影。机制上就是前面说的把输入特征先弄低位压缩再高维投影，最后乘一个缩放因子加到基座模型原始输出后面的residual  - 的一个旁路残差结构。

LoRA 注入新知识能力很弱，效果有限。一般来说，只有显存紧张的时候会用 LoRA / QLoRA。或者一个底座服务多任务、需要频繁迭代的时候考虑 LoRA（多 adapter 热插拔）。如果**知识风格、格式**需要对齐，在**中小数据量**下勉强是 LoRA 的甜点区。

**实践 / 提高 LoRA 上限的做法**：增大 `r`、覆盖更多 `target_modules`（不止 attention（Transformer 中最常见加 LoRA 的地方），也加 MLP（FFN）的 `gate/up/down_proj`（实际工程中经常只给 Q/V 或 Q/K/V/O 加 LoRA）、或用 DoRA、rsLoRA 等变体。

**关键超参数配置：**

- `r` (Rank): 通常设置为 8 到 64。如果任务较复杂，可适当增大。
- `lora_alpha`: 通常设置为 $2 \times r$。
- `target_modules`: **不要只微调 `q_proj` 和 `v_proj`**。将 LoRA 应用于所有线性层（包括 `k_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj`）可以获得更接近全量微调的效果。

**BTW, 那么 QLoRA 是什么：**

前面其实偷偷提了，即 4-bit Quantization + LoRA

核心思想：

- Base Model：4-bit quantization
- Base Model：冻结
- LoRA：FP16/BF16 训练

这样可以进一步降低显存，使单卡微调更大的模型成为可能。

#### 3. 样本拼接（Sample Packing）

* **问题：** 不同的对话样本长度差异很大。如果简单地将它们 Padding（填充）到最大长度（如 4096），会导致显存中存在大量的 Padding Token（如 `<pad>`），浪费计算资源。
* **解决方案：**
  * 采用 **Packing** 技术，将多个短样本拼接成一条达到最大长度（如 4096）的长样本，中间用 EOS（End of Sequence）Token 隔开。
  * 在注意力计算时，需要配合 **Block Diagonal Attention（块对角注意力）**，防止样本 A 的输入关注到同一个拼接序列中样本 B 的内容。主流框架如 Hugging Face TRL 库中的 `SFTTrainer` 提供了 `packing=True` 选项。

#### 5. 核心超参数的调试（Hyperparameter Tuning）

SFT 对超参数比较敏感，以下是常见的经验范围：

* **学习率（Learning Rate, LR）：**
  * 全参数微调：通常设得很小，一般在 `5e-6` 到 `2e-5` 之间。过大会破坏预训练权重。
  * **Scheduler：** 推荐使用带 Warmup 的 Cosine 学习率衰减策略（Cosine Annealing）。
* **Batch Size：**
  * 全局 Batch Size（Global Batch Size）通常在 128 到 512 之间。可以通过 Gradient Accumulation（梯度累积）来调整，以适应单卡显存限制。
* **Epoch 数量：**
  * 通常只需要 **1 到 3 个 Epoch**。SFT 阶段极易过拟合。过多的 Epoch 会导致模型丧失泛化能力，回答变得机械化和单一。

#### 6. 基础设施与分布式并行

* **精度选择：** 训练时使用 **BF16**（Bfloat16），相比于 FP16，BF16 的动态范围更大，不容易发生溢出（Overflow/Underflow），训练更稳定。
* **显存优化技术：**
  * **Gradient Checkpointing（梯度检查点）：** 用时间换空间。不保存前向传播的所有激活值，而在反向传播时重新计算，能显著降低显存占用。
  * **FlashAttention-2 ：** 必须启用的算子优化，可成倍提升计算速度并降低 Attention 机制的显存开销。
  * **分布式框架：** 常用 DeepSpeed（ZeRO-2 或 ZeRO-3）、FSDP（PyTorch Fully Sharded Data Parallel）或 Megatron-LM（适合超大规模模型）。对于中等规模模型（如 7B - 70B），DeepSpeed ZeRO-3 是MLE最常用的选择。

#### 7. 评估与避坑指南（Evaluation & Caveats）

* **不健康的 Loss：**
  不要盲目追求极低的验证集 Loss。如果 Loss 接近于 0，通常意味着模型对特定的模板或话术产生了严重的过拟合，在实际对话中其表现可能极差。
* **EOS Token 丢失问题：**
  在数据处理时，确保每个 Assistant 回答的末尾都添加了 `<eos>`（End of Sequence）Token，并且该 Token 参与了 Loss 计算。如果模型没有学会何时输出 `<eos>`，在实际推理时它会喋喋不休，直到达到最大长度限制。
* **多维度评估机制：**
  * *自动评估（Benchmark）：* 如使用 MMLU、GSM8K 等测试基础能力是否退化。
  * *LLM-as-a-Judge（大模型充当裁判）：* 使用 GPT-4 或更强的模型对微调后的模型输出与 baseline 进行 Pairwise（成对）对比，给出评分。
  * *人工评测（Human Evaluation）：* 针对特定业务场景，制定详尽的标注指南进行盲测（Double-blind test）。

# Shift Right

LLM 训练中**Shift Right（右移）核心的数据对齐操作**。它的核心目的是**确保自回归（Autoregressive）模型在预测时遵循因果性（Causality）**，即“只能根据当前及历史的 Token，去预测下一个 Token”。

根据模型架构的不同（Decoder-Only 或 Encoder-Decoder），Shift Right 的具体实现方式和所处的 SFT 阶段也有所不同。

---

### 一、 Shift Right 的两种具体实现

#### 1. Decoder-Only 架构（如 LLaMA, GPT, Qwen 等主流模型）

在目前最主流的 Decoder-Only 模型中，Shift Right 主要体现在**损失计算时的错位对齐**。

* **原理：**
  自回归模型在位置 $t$ 输出的概率分布（Logits），对应的是对位置 $t+1$ 处 Token 的预测。
  若输入序列为 `[T0, T1, T2, T3]`，模型的前向传播会输出 4 个位置的预测 Logits：
  
  * `Logits[0]`（由 `T0` 产生）用来预测 `T1`
  * `Logits[1]`（由 `T0, T1` 产生）用来预测 `T2`
  * `Logits[2]`（由 `T0, T1, T2` 产生）用来预测 `T3`
  * `Logits[3]`（由整个序列产生）没有下一个真实的标签（`T4`）可以对比。
* **对齐操作：**
  为了计算交叉熵损失（Cross-Entropy Loss），我们需要将预测值（Logits）与真实标签（Labels）进行对齐：
  
  * 舍弃 Logits 的最后一个位置（因为没有对应的真实标签可预测）。
  * 舍弃 Labels 的第一个位置（因为没有输入可以用来预测第一个 Token）。
  
  在 PyTorch 代码中，这一步通常表现为：
  
  ```python
  # 舍弃 logits 最后一个位置，舍弃 labels 第一个位置
  shift_logits = logits[..., :-1, :].contiguous()
  shift_labels = labels[..., 1:].contiguous()
  
  # 计算损失
  loss = loss_fct(shift_logits.view(-1, shift_logits.size(-1)), shift_labels.view(-1))
  ```

#### 2. Encoder-Decoder 架构（如 T5, BART 等 Seq2Seq 模型）

在这种架构中，Shift Right 指的是**构建解码器输入（Decoder Input IDs）**的过程。

* **原理：**
  Decoder 训练时也需要因果掩码。为了预测 Target 序列 `[T1, T2, T3]`，Decoder 的第一步输入不能是 `T1`（否则会发生数据泄露），而必须是一个起始符（如 `<bos>` 或 `<pad>`），然后逐步把真实的 Label 向右移动一格输入给 Decoder。
* **对齐操作：**
  将原始 Target 整体右移一格，最前面补上一个起始符。
  例如，Label 是 `[A, B, C]`：
  右移后变为 `[<bos>, A, B]`，这部分作为 `decoder_input_ids` 喂给 Decoder。
  
  在 Hugging Face 源码中，通常通过 `shift_tokens_right` 函数实现：
  
  ```python
  def shift_tokens_right(input_ids: torch.Tensor, pad_token_id: int, decoder_start_token_id: int):
      shifted_input_ids = input_ids.new_zeros(input_ids.shape)
      # 将 input_ids 整体向右移动一位
      shifted_input_ids[:, 1:] = input_ids[:, :-1].clone()
      # 最前方填入解码器开始标记
      shifted_input_ids[:, 0] = decoder_start_token_id
      return shifted_input_ids
  ```

---

### 二、 它用在 SFT 的哪个阶段？

在大模型 SFT 训练的完整流水线中，根据你使用的模型架构，Shift Right 发生在不同的阶段：

#### 阶段 A：数据整理与前向传播构建阶段（Data Collator / Forward Input Preparation）

* **适用架构：** **Encoder-Decoder 架构**（如 T5, BART）。
* **具体过程：**
  在 DataLoader 拼装 Batch 数据的阶段（Data Collator），或者在模型 `forward` 的最开始阶段。
  代码会将原始 `labels` 经过 `shift_tokens_right` 处理，生成 `decoder_input_ids`，然后将 `input_ids`（Encoder 的输入）、`decoder_input_ids`（Decoder 的输入）和 `labels` 一并送入模型进行训练。

#### 阶段 B：前向传播结束与损失计算阶段（Post-Forward / Loss Calculation）

* **适用架构：** **Decoder-Only 架构**（如 LLaMA, Qwen 等主流大语言模型）。
* **具体过程：**
  这是最常见的情况。此时，Data Collator 阶段并不会做右移操作。
  1. 你的输入 `input_ids`（包含 Prompt 和 Response）被直接送入模型，执行前向传播（Forward Pass），得到 `logits`。
  2. 在**计算 Loss 的那一刻**，代码会在显存中对 `logits` 和 `labels` 执行 `[:-1]` 和 `[1:]` 的切片操作（即上面提到的错位对齐）。
  3. 对齐后，再通过带有掩码的 Cross Entropy（如忽略标签为 `-100` 的 Prompt 部分）计算出最终的 SFT 损失并进行反向传播。

---

在 SFT 中，我们通常会把 Prompt 部分的 Label 设为 `-100`。在做 `labels[:, 1:]` 切片时，对应的 `-100` 位置也会发生相应的右移，这由 PyTorch 的切片机制天然保证，但手动实现自定义 Loss 时务必注意不要把对齐顺序弄反。

### 三、 作为 MLE 需要注意的关键细节

1. **`-100` 的处理：**
   在 SFT 中，我们通常会把 Prompt 部分的 Label 设为 `-100`。在做 `labels[:, 1:]` 切片时，对应的 `-100` 位置也会发生相应的右移，这由 PyTorch 的切片机制天然保证，但手动实现自定义 Loss 时务必注意不要把对齐顺序弄反。
2. **验证集评估（Evaluation）时的一致性：**
   在评估模型验证集 Loss 时，必须使用与训练阶段**完全相同**的 Shift 逻辑，否则算出来的困惑度（Perplexity, PPL）或 Loss 会出现偏差，导致无法准确评估模型性能。
3. **Hugging Face 自动处理：**
   大多数主流的 Hugging Face 预训练模型（如 `LlamaForCausalLM`）在它们的 `forward` 函数内部**已经自动写好了**针对 Decoder-Only 的 `shift` 逻辑。如果你直接将 `labels` 传给模型，模型会在内部完成错位对齐并直接返回 Loss；但如果你提取出 `logits` 自己手动写 Loss 计算，或者在使用某些自定义并行框架时，则需要你手动编写 `logits[..., :-1, :]` 和 `labels[..., 1:]` 的对齐逻辑。

## 三、机器学习工程师必须知道的工程细节

<details>
<summary><b>点开：8 条"血泪"级注意事项</b></summary>

1. **Chat template 必须与推理端完全一致**：训练用什么特殊 token（`<|im_start|>`、`[INST]`、`<|assistant|>` 等）、什么拼接顺序，推理时就必须一模一样，否则直接触发训练/推理分布不匹配。用 `tokenizer.apply_chat_template()` 统一管理。
2. **EOS 必须参与训练且被算 loss**：否则模型学不会"停下来"，推理时会无限生成。
3. **Loss mask 用 `ignore_index=-100`**：PyTorch `CrossEntropyLoss` 对 `-100` 的位置自动跳过。prompt token 的 label 设为 `-100`。
4. **超参**：全参微调 LR 通常 $1\text{e-}5 \sim 2\text{e-}5$；LoRA 可到 $1\text{e-}4 \sim 3\text{e-}4$。**Epoch 只需 1~3**，过多会过拟合 + 灾难性遗忘。warmup + cosine/linear 衰减。
5. **样本 packing**：把多条短样本拼进一个定长序列以提高 GPU 利用率，但**必须用 block-diagonal attention mask**（FlashAttention 的 `varlen` / `attention mask`）防止跨样本注意力污染，否则 A 样本能"看到"B 样本。
6. **数据质量 > 数量**（LIMA 结论）：几千~几万条高质量、多样化数据往往优于百万条噪声数据。
7. **灾难性遗忘**：SFT 可能损害预训练能力，可混入少量通用/预训练数据、降低 LR、用 LoRA 缓解。
8. **右侧 padding + 忽略 pad 的 loss**；attention mask 要正确标注 pad 位置。

</details>

## 四、可运行代码片段

### 片段 1：数据处理 —— 构造带 loss mask 的 labels（最核心）

```python
import torch
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
IGNORE_INDEX = -100

def build_example(messages):
    """
    messages: [{"role":"user","content":...}, {"role":"assistant","content":...}, ...]
    只对 assistant 回答（含 EOS）计算 loss，其余 mask 成 -100。
    """
    input_ids, labels = [], []
    for msg in messages:
        # 单独渲染每一段，拿到该段的 token 边界
        seg = tokenizer.apply_chat_template(
            [msg], tokenize=True, add_generation_prompt=False
        )
        input_ids += seg
        if msg["role"] == "assistant":
            labels += seg                       # 回答段：算 loss
        else:
            labels += [IGNORE_INDEX] * len(seg) # 指令/系统段：mask 掉

    return {
        "input_ids": torch.tensor(input_ids),
        "labels": torch.tensor(labels),
        "attention_mask": torch.ones(len(input_ids), dtype=torch.long),
    }

ex = build_example([
    {"role": "user", "content": "1+1等于几？"},
    {"role": "assistant", "content": "等于 2。"},
])
print("被计入 loss 的 token 数:", (ex["labels"] != IGNORE_INDEX).sum().item())
```

> 生产中更稳妥的做法是用 `return_assistant_tokens_mask=True`（新版 `apply_chat_template` 支持）或在模板中标注 `{% generation %}` 区块来自动获取回答掩码，避免逐段拼接时特殊 token 对不齐。

### 片段 2：手写 SFT loss（看清 shift + mask + 归一化）

```python
import torch.nn.functional as F

def sft_loss(logits, labels, reduction="token_mean"):
    """
    logits: [B, T, V]   labels: [B, T] (prompt 位置为 -100)
    """
    # 1) label shift：用第 i 个位置预测第 i+1 个 token
    shift_logits = logits[:, :-1, :].contiguous()   # [B, T-1, V]
    shift_labels = labels[:, 1:].contiguous()       # [B, T-1]

    # 2) 逐 token 交叉熵，-100 自动被忽略
    loss_flat = F.cross_entropy(
        shift_logits.view(-1, shift_logits.size(-1)),
        shift_labels.view(-1),
        ignore_index=-100,
        reduction="none",
    )                                                # [B*(T-1)]

    mask = (shift_labels.view(-1) != -100).float()

    if reduction == "token_mean":                    # 全 batch 有效 token 平均
        return (loss_flat * mask).sum() / mask.sum().clamp(min=1)
    elif reduction == "sample_mean":                 # 每条样本等权
        loss_flat = loss_flat.view(shift_labels.size())
        mask = mask.view(shift_labels.size())
        per_sample = (loss_flat * mask).sum(-1) / mask.sum(-1).clamp(min=1)
        return per_sample.mean()
```

### 片段 3：梯度累积下的正确归一化（避坑）

```python
# ❌ 错误：每个 micro-batch 有效 token 数不同，除以 steps 会算错权重
# loss = sft_loss(...) / grad_accum_steps; loss.backward()

# ✅ 正确：按累积窗口的“总有效 token 数”归一化
optimizer.zero_grad()
total_tokens = sum((b["labels"][:, 1:] != -100).sum() for b in micro_batches)
for b in micro_batches:
    out = model(input_ids=b["input_ids"], attention_mask=b["attention_mask"])
    # 用 sum 而非 mean，最后统一除以窗口总 token 数
    loss_sum = sft_loss_sum(out.logits, b["labels"])   # 返回未归一化的 sum
    (loss_sum / total_tokens).backward()
optimizer.step()
```

### 片段 4：LoRA —— 参数高效微调的数学与实现

LoRA 冻结原权重 $W_0 \in \mathbb{R}^{d\times k}$，只训练低秩增量：

$$
W = W_0 + \Delta W = W_0 + \frac{\alpha}{r}\,B A,\qquad B\in\mathbb{R}^{d\times r},\; A\in\mathbb{R}^{r\times k},\; r \ll \min(d,k)
$$

$A$ 用高斯初始化、$B$ 初始化为 0，保证训练起点 $\Delta W = 0$（不破坏预训练权重）。可训练参数量从 $dk$ 降到 $r(d+k)$。

```python
from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-0.5B-Instruct", torch_dtype=torch.bfloat16
)
lora_cfg = LoraConfig(
    r=16, lora_alpha=32, lora_dropout=0.05, bias="none",
    task_type="CAUSAL_LM",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
)
model = get_peft_model(model, lora_cfg)
model.print_trainable_parameters()  # 通常 <1% 参数可训练
```

### 片段 5：完整最小训练循环骨架

```python
from torch.optim import AdamW
from transformers import get_cosine_schedule_with_warmup

model.train()
optimizer = AdamW(model.parameters(), lr=2e-4)   # LoRA 用较大 LR
total_steps = len(dataloader) * num_epochs
scheduler = get_cosine_schedule_with_warmup(
    optimizer, num_warmup_steps=int(0.03 * total_steps),
    num_training_steps=total_steps,
)

for epoch in range(num_epochs):
    for batch in dataloader:
        out = model(input_ids=batch["input_ids"],
                    attention_mask=batch["attention_mask"])
        loss = sft_loss(out.logits, batch["labels"], reduction="token_mean")

        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)  # 梯度裁剪
        optimizer.step()
        scheduler.step()
        optimizer.zero_grad()
```
