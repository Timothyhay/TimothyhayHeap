SFT 和预训练一样，都是在学习：给定前面的 token，预测下一个 token。而 SFT 阶段更多地把预训练模型的概率分布重新往目标行为偏移。

在完成预训练时，模型具备强大的语言理解和生成能力，但还只是一个无情 Next-Token Prediction 机器，不理解问答或指令遵从的范式；有监督的问答序列数据训练，
让模型理解以指令遵从和对话的方式安心当一只豆包或者橙色章鱼，此时模型被 align 到助手的角色。

# 1. SFT的过程

数据准备与格式化：将原始的指令和回答拼接成特定 Chat Template。
标签掩码（Label Masking / Target-only Loss）：在计算损失（Loss）时，只对模型的回答（Response）部分计算 Loss，而对输入的提示词（Prompt/Instruction）进行遮蔽（通常设为 -100），避免模型去“预测”输入本身。
动态填充与 Batch 组装：在同一个 Batch 内对不同长度的文本进行 Padding，并设置相应的 attention_mask。
对不同的训练框架，上述数据处理过程可能包含格式的转换。当使用 Megatron Mind
模型加载与高效微调配置：加载预训练模型，并引入 PEFT（如 LoRA）以节省显存。
前向传播与反向传播循环：通过自回归（Autoregressive）方式计算交叉熵损失，并更新模型参数。

> MindSpeed 并没有完全重写一套 Megatron，而是用 Monkey Patch 在运行时动态地拦截 Megatron-LM 的底层调用，将其中的 GPU 特有算子、CUDA 相关的通信组件等，无缝替换为适配昇腾 NPU、CANN 以及 HCCL 的高性能算子。因为类似的原因，MindSpeed 也支持 FSDP 推理后端。如果使用 Megatron，就需要把模型和数据都转为 Megatron 的专有格式，来适配并行各种模型切分

从数学上看：

预训练模型本质是在学习：$P(x_t|x_{\lt t})$

SFT 也并没有改变这个目标。仍然是：$\max_{\theta}\sum \log P_{\theta}(y_t|x,y_{\lt t})$

其中：

* (x) 是 Prompt
* (y) 是 Answer

# 二、SFT Loss是什么

本质就是 Cross Entropy。

设真实 token：$y_t$，模型输出 logits：$z_t$，softmax：$p_t=\text{softmax}(z_t)$

loss：
$$
L=-\sum_t \log p_t(y_t)
$$

或者平均：

[
L=-\frac1N\sum_t \log p_t(y_t)
]

这是整个 SFT 的核心。

很多复杂训练最后都在优化这个东西。

# 三、为什么SFT能改变模型行为

假设预训练模型：

```text
Prompt:
Python如何读取文件？
```

原来概率：

| Token  | Prob |
| ------ | ---- |
| 可以     | 0.4  |
| Python | 0.2  |
| 使用     | 0.1  |

SFT样本总是：

```text
可以使用 open() 函数...
```

训练后：

[
P(\text{可以})↑
]

[
P(\text{使用})↑
]

[
P(\text{open})↑
]

大量样本累计后：

整个回答风格发生迁移。

因此：

SFT本质是：

> 对条件概率分布进行局部重塑。

# 四、训练时哪些Token参与Loss

这是工程里极重要的知识。

通常：

```text
User:
你好

Assistant:
你好，请问有什么可以帮助你？
```

不会计算 User 部分。

Mask：

```text
User:      -100
你好       -100

Assistant: 你好
请问
...
```

即：

```python
labels = [
    -100,
    -100,
    ...
    token1,
    token2,
    ...
]
```

loss只计算Assistant部分。

否则模型会学：

```text
User:
你好
```

这种无意义预测。

# 五、Completion-Only SFT

现代模型几乎都这么做。

例如：

```text
<|user|>
...

<|assistant|>
...
```

loss mask：

```text
User部分      mask
Assistant部分 unmask
```

即：

[
L
=

-\sum_{t\in assistant}
\log P(y_t)
]

这是当前主流。

你提到的 Agent Trajectory：

例如：

Observation:

Thought:

到底训练哪些部分？

## 方案1：全部训练

```text
Thought
Action
Observation
Final
```

全部计算loss。

优点：

* 学习完整轨迹

缺点：

* Observation实际上是环境输出
* 不应该学习

## 方案2：Mask Observation

训练：

```text

Action
Final
```

Mask：

```text

```

这样更合理。

很多 Agent SFT 都这样做。

# 七、Teacher Forcing

SFT最大特点：

Teacher Forcing。

例如：

真实答案：

```text
ABCDEF
```

训练时：

预测 B：

输入：

```text
A
```

预测 C：

输入：

```text
AB
```

预测 D：

输入：

```text
ABC
```

永远喂真实历史。

即：

[
P(y_t|y_{<t}^{gold})
]

而不是：

[
P(y_t|\hat y_{<t})
]

---

# 八、Exposure Bias

Teacher Forcing带来经典问题：

训练：

```text
ABCDEF
```

推理：

```text
ABX???
```

一旦生成错：

后续输入变了。

因此：

训练和推理分布不一致。

称为：

[
P_{train}\neq P_{infer}
]

即 Exposure Bias。

这也是后来 RLHF、DPO、RFT 出现的重要原因之一。

# 九、长序列SFT的特殊问题

对于你的Agent轨迹（80k token）尤其重要。

## Loss Dilution

假设：

```text
前面79000 token
后面1000 token
```

真正重要的是最后：

```text
Final Answer
```

但loss平均：

[
L=\frac1N\sum l_t
]

则：

Final部分梯度被稀释。

---

常见做法：

### 加权Loss

[
L=
\sum w_t l_t
]

例如：

```text
Thought      0.2
Action       1.0
Final Answer 3.0
```

提高最终答案权重。

# 十、Packing

SFT工程里非常重要。

假设：

样本长度：

```text
200
300
500
```

Context：

```text
4096
```

直接训练浪费。

Packing：

```text
Sample1 <eos>
Sample2 <eos>
Sample3
```

拼成：

```text
1000 token
```

一次训练。

GPU利用率大幅提升。

很多训练吞吐量可以提升：

20%~60%。

# 十一、LoRA-SFT在干什么

LoRA实际上没有改变SFT目标。

原权重：

[
W
]

变成：

[
W' = W+\Delta W
]

其中：

[
\Delta W = BA
]

且：

[
rank=r
]

训练：

[
A,B
]

冻结：

[
W
]

loss仍然：

[
L=-\log P(y)
]

完全一样。

只是参数更少。

# 十二、SFT数据质量比数量更重要

经验上：

很多团队会发现：

```text
100M 高质量token
```

往往胜过：

```text
1B 垃圾token
```

因为SFT是在改变行为而非学习世界知识。

其核心不是覆盖率，而是：

[
P(\text{desired behavior})
]

的强化。

对于 Agent 数据尤其如此：

* 正确轨迹
* 完整轨迹
* 多样化失败案例
* 高质量工具调用

比单纯堆数据量更重要。

# 十三、作为训练工程师最应该掌握什么

如果你的工作涉及训练 Qwen/Llama 类模型，我认为至少应该深入理解下面几个层次：

### 第一层（必须掌握）

* Tokenization
* Cross Entropy
* Teacher Forcing
* Loss Mask
* Gradient Accumulation
* Mixed Precision
* Packing

这是日常训练离不开的知识。

---

### 第二层（Agent训练必须掌握）

* Long Context训练
* RoPE Scaling
* Sequence Parallelism
* Agent Trajectory SFT
* Tool Call Formatting
* Loss Weighting

因为这些直接决定 Agent 能否学会推理和工具使用。

---

### 第三层（研究人员级别）

* DPO
* PPO
* GRPO
* RFT
* Process Supervision
* Synthetic Data Generation
* Curriculum Learning

这是当前后训练（Post-training）领域最活跃的方向。

---

对于你目前的场景（长 Agent 轨迹、Qwen 系列、计划训练自己的 Agent 模型），真正值得深入研究的其实已经不是「普通 SFT」，而是：

> **长轨迹 Agent SFT 的梯度传播、Credit Assignment、Trajectory Packing、Observation Masking、Loss Reweighting 和后续 DPO/RFT 衔接。**

这些问题往往比模型结构本身更决定最终 Agent 能力。甚至很多 Agent 项目 80% 的效果差异，都来自数据与 SFT 设计，而不是底座模型。


谢谢你的反馈。我同意，对于已经参与模型训练的人来说，过多的项目符号和代码块会打断逻辑链条。真正有价值的内容应该像一篇技术讲义，而不是培训 PPT。那我尝试用更连贯的方式重新组织一下预训练的原理，并把一些通常被简化掉的关键点补充进去。

从机器学习的角度看，今天的大语言模型预训练实际上是在解决一个极其简单的问题：给定一个 token 序列 (x_1,x_2,\dots,x_n)，学习其联合概率分布

[
P(x_1,x_2,\dots,x_n)
]

由于直接建模联合分布非常困难，根据概率链式法则，我们把它分解为：

[
P(x_1,x_2,\dots,x_n)
====================

\prod_{t=1}^{n}
P(x_t|x_{<t})
]

于是训练目标就变成了学习每一个条件概率 (P(x_t|x_{<t}))。这就是所谓的 Next Token Prediction。无论是 GPT-4、Claude、Qwen 还是 Llama，其预训练目标本质上都没有脱离这个框架。

很多初学者看到这里会产生一个疑问：如果训练目标只是预测下一个词，那么模型为什么会学会数学、代码、推理、规划甚至某种程度上的常识？这实际上是预训练最核心的地方。

假设你想预测一句话中的最后一个词：

“牛顿发现了______定律。”

如果模型想提高预测准确率，它必须知道牛顿是谁，什么叫发现，什么叫定律，以及历史上哪些定律与牛顿有关。如果它不知道这些知识，它就无法降低 loss。因此，预测任务虽然表面上是在预测 token，但从优化的角度看，它被迫建立一个能够解释数据生成过程的内部表示。换句话说，模型并不是主动学习知识，而是在降低预测误差的过程中被迫构建知识。

这也是为什么很多研究者更喜欢把 LLM 理解成一种世界模型（World Model）而不是知识库。参数里存储的并不是一条条事实，而是一套能够生成这些事实的统计结构。

训练过程中，Transformer 通过反向传播不断调整参数。设模型参数为 (\theta)，训练数据集为 (D)，则最大似然目标可以写成：

[
\max_\theta
\sum_{x \in D}
\sum_t
\log P_\theta(x_t|x_{<t})
]

对应的损失函数是交叉熵：

[
L
=

-\frac1N
\sum_t
\log P_\theta(x_t|x_{<t})
]

对于训练工程师来说，一个重要的认识是：预训练并不直接优化“知识”“推理”或者“智能”，它只优化交叉熵。所有高级能力最终都必须通过“降低交叉熵”这一条路径间接产生。如果某种能力不能帮助模型更好地预测未来 token，那么梯度下降就没有理由学习它。

接下来需要理解 Transformer 在这里扮演什么角色。Attention 机制的出现，本质上解决的是长期依赖问题。传统 RNN 很难利用几千个 token 之前的信息，而 Transformer 允许当前位置直接访问上下文中的任意位置。其核心公式为：

[
Attention(Q,K,V)
================

softmax
\left(
\frac{QK^T}{\sqrt d}
\right)V
]

这里的含义并不神秘。对于当前 token，模型首先计算它与历史所有 token 的相关性，然后根据相关性加权聚合历史信息。经过大量训练后，不同的 Attention Head 会逐渐形成专门化功能。有些 Head 负责代词指代，有些负责括号匹配，有些负责代码结构，有些负责数学符号关系。这些现象已经被大量 Mechanistic Interpretability 研究观察到。

真正有趣的地方在于，当参数规模和数据规模持续增长时，模型内部会逐渐形成越来越抽象的表示。早期层可能学习词法和语法，中间层学习概念和实体关系，高层则学习更复杂的抽象结构。这种层级表示与人脑皮层中从低级特征到高级语义的处理方式有一定相似性，虽然两者机制完全不同。

从训练工程的角度看，预训练最重要的问题其实不是模型结构，而是数据分布。因为模型学到的不是“真理”，而是数据中的统计规律。如果某类模式在数据中占比更高，模型就会更倾向于学习它。例如一个模型如果训练语料中代码占 30%，另一个模型代码只占 5%，即使参数量完全相同，它们的代码能力也会有巨大差异。今天很多开源模型之间的性能差距，很大程度上来自数据配方（Data Mixture）而不是架构创新。

这也是为什么现代预训练越来越强调数据工程。预训练团队花费大量时间进行去重、质量过滤、文档分类和数据配比，并不是因为这些工作很优雅，而是因为数据分布最终决定了模型学到什么样的世界模型。对于一个 70B 参数模型而言，如果训练数据中几乎没有高质量数学证明，那么它几乎不可能凭空涌现出很强的数学推理能力。

进一步说，预训练实际上存在一种知识压缩过程。假设一个 70B 模型使用 bfloat16 存储，其参数容量大约只有 140GB。但它可能阅读了十几万 GB 的文本数据。这意味着模型不可能逐字记忆训练集，而必须把大量冗余信息压缩成更抽象的结构。因此我们看到模型能够泛化到从未见过的问题。它记住的不是具体句子，而是生成这些句子的底层规律。

在大规模训练中，还有一个极其重要的经验规律叫 Scaling Law。研究者发现，当参数量、数据量和训练计算量同步增加时，训练损失会按照幂律下降，大致满足：

[
L(C)
====

A C^{-\alpha}
+
B
]

其中 (C) 是计算预算。这意味着模型性能不会突然饱和，而是持续改善，只是边际收益越来越低。这一发现极大改变了整个行业的发展方向，因为它说明堆算力、堆数据、堆参数并非盲目行为，而是一种有理论依据的工程路线。

后来 DeepMind 的 Chinchilla 工作进一步发现，很多模型实际上处于“参数过多、数据不足”的状态。对于固定计算预算而言，适当减小模型规模、增加训练 token 数量，反而可以获得更好的结果。这也是为什么现代模型越来越重视数据量，许多模型的预训练 token 已经达到十万亿级别。

如果把整个 LLM 训练流程放在一起理解，我认为最准确的认知框架是：预训练阶段负责建立压缩后的世界模型，使模型能够理解语言、知识和现实世界中的统计结构；SFT 阶段负责把这个世界模型转换为符合人类期望的行为模式；而 DPO、RLHF、GRPO、RFT 等后训练阶段，则是在行为空间中进一步优化偏好、推理和决策能力。

因此，对于真正参与训练的人来说，预训练最值得深入理解的其实不是“预测下一个 token”这句话本身，而是三个更深层的问题：第一，为什么仅靠预测 token 就能形成世界模型；第二，数据分布如何决定最终能力边界；第三，梯度下降为什么会在超大规模参数空间中自发形成抽象表示。这三个问题至今仍然是大模型研究最核心、也最有趣的部分。
