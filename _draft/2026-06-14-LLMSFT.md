SFT 和预训练一样，都是在学习：给定前面的 token，预测下一个 token。而 SFT 阶段更多地把预训练模型的概率分布重新往目标行为偏移。

在完成预训练时，模型具备强大的语言理解和生成能力，但还只是一个无情 Next-Token Prediction 机器，不理解问答或指令遵从的范式；有监督的问答序列数据训练，
让模型理解以指令遵从和对话的方式安心当一只豆包或者橙色章鱼，此时模型被 align 到助手的角色。

# 一、SFT的过程

数据准备与格式化：将原始的指令和回答拼接成特定模板（Chat Template）。
标签掩码（Label Masking / Target-only Loss）：在计算损失（Loss）时，只对模型的回答（Response）部分计算 Loss，而对输入的提示词（Prompt/Instruction）进行遮蔽（通常设为 -100），避免模型去“预测”输入本身。
动态填充与 Batch 组装：在同一个 Batch 内对不同长度的文本进行 Padding，并设置相应的 attention_mask。
模型加载与高效微调配置：加载预训练模型，并引入 PEFT（如 LoRA）以节省显存。
前向传播与反向传播循环：通过自回归（Autoregressive）方式计算交叉熵损失，并更新模型参数。

从数学上看：

预训练模型本质是在学习：$P(x_t|x_{\lt t})$

SFT 也并没有改变这个目标。仍然是：$\max_{\theta}\sum \log P_{\theta}(y_t|x,y_{\lt t})$

其中：

* (x) 是 Prompt
* (y) 是 Answer

# 二、SFT Loss是什么

本质就是 Cross Entropy。

设真实 token：$y_t$，模型输出 logits：$z_t$，softmax：$p_t=\text{softmax}(z_t)$

loss：
$$
L=-\sum_t \log p_t(y_t)
$$

或者平均：

[
L=-\frac1N\sum_t \log p_t(y_t)
]

这是整个 SFT 的核心。

很多复杂训练最后都在优化这个东西。

# 三、为什么SFT能改变模型行为

假设预训练模型：

```text
Prompt:
Python如何读取文件？
```

原来概率：

| Token  | Prob |
| ------ | ---- |
| 可以     | 0.4  |
| Python | 0.2  |
| 使用     | 0.1  |

SFT样本总是：

```text
可以使用 open() 函数...
```

训练后：

[
P(\text{可以})↑
]

[
P(\text{使用})↑
]

[
P(\text{open})↑
]

大量样本累计后：

整个回答风格发生迁移。

因此：

SFT本质是：

> 对条件概率分布进行局部重塑。

# 四、训练时哪些Token参与Loss

这是工程里极重要的知识。

通常：

```text
User:
你好

Assistant:
你好，请问有什么可以帮助你？
```

不会计算 User 部分。

Mask：

```text
User:      -100
你好       -100

Assistant: 你好
请问
...
```

即：

```python
labels = [
    -100,
    -100,
    ...
    token1,
    token2,
    ...
]
```

loss只计算Assistant部分。

否则模型会学：

```text
User:
你好
```

这种无意义预测。

---

# 五、Completion-Only SFT

现代模型几乎都这么做。

例如：

```text
<|user|>
...

<|assistant|>
...
```

loss mask：

```text
User部分      mask
Assistant部分 unmask
```

即：

[
L
=

-\sum_{t\in assistant}
\log P(y_t)
]

这是当前主流。

# 六、为什么Agent数据和普通对话不一样

你提到的 Agent Trajectory：

例如：

```text
User:
帮我分析仓库

Thought:
先读取README

Action:
read_file()

Observation:
...

Thought:
继续分析

Action:
...
```

这里出现问题：

到底训练哪些部分？

---

## 方案1：全部训练

```text
Thought
Action
Observation
Final
```

全部计算loss。

优点：

* 学习完整轨迹

缺点：

* Observation实际上是环境输出
* 不应该学习

---

## 方案2：Mask Observation

训练：

```text
Thought
Action
Final
```

Mask：

```text
Observation
```

这样更合理。

很多 Agent SFT 都这样做。

# 七、Teacher Forcing

SFT最大特点：

Teacher Forcing。

例如：

真实答案：

```text
ABCDEF
```

训练时：

预测 B：

输入：

```text
A
```

预测 C：

输入：

```text
AB
```

预测 D：

输入：

```text
ABC
```

永远喂真实历史。

即：

[
P(y_t|y_{<t}^{gold})
]

而不是：

[
P(y_t|\hat y_{<t})
]

---

# 八、Exposure Bias

Teacher Forcing带来经典问题：

训练：

```text
ABCDEF
```

推理：

```text
ABX???
```

一旦生成错：

后续输入变了。

因此：

训练和推理分布不一致。

称为：

[
P_{train}\neq P_{infer}
]

即 Exposure Bias。

这也是后来 RLHF、DPO、RFT 出现的重要原因之一。

---

# 九、长序列SFT的特殊问题

对于你的Agent轨迹（80k token）尤其重要。

## Loss Dilution

假设：

```text
前面79000 token
后面1000 token
```

真正重要的是最后：

```text
Final Answer
```

但loss平均：

[
L=\frac1N\sum l_t
]

则：

Final部分梯度被稀释。

---

常见做法：

### 加权Loss

[
L=
\sum w_t l_t
]

例如：

```text
Thought      0.2
Action       1.0
Final Answer 3.0
```

提高最终答案权重。

# 十、Packing

SFT工程里非常重要。

假设：

样本长度：

```text
200
300
500
```

Context：

```text
4096
```

直接训练浪费。

Packing：

```text
Sample1 <eos>
Sample2 <eos>
Sample3
```

拼成：

```text
1000 token
```

一次训练。

GPU利用率大幅提升。

很多训练吞吐量可以提升：

20%~60%。

# 十一、LoRA-SFT在干什么

LoRA实际上没有改变SFT目标。

原权重：

[
W
]

变成：

[
W' = W+\Delta W
]

其中：

[
\Delta W = BA
]

且：

[
rank=r
]

训练：

[
A,B
]

冻结：

[
W
]

loss仍然：

[
L=-\log P(y)
]

完全一样。

只是参数更少。

---

# 十二、SFT数据质量比数量更重要

经验上：

很多团队会发现：

```text
100M 高质量token
```

往往胜过：

```text
1B 垃圾token
```

因为SFT是在改变行为而非学习世界知识。

其核心不是覆盖率，而是：

[
P(\text{desired behavior})
]

的强化。

对于 Agent 数据尤其如此：

* 正确轨迹
* 完整轨迹
* 多样化失败案例
* 高质量工具调用

比单纯堆数据量更重要。

---

# 十三、作为训练工程师最应该掌握什么

如果你的工作涉及训练 Qwen/Llama 类模型，我认为至少应该深入理解下面几个层次：

### 第一层（必须掌握）

* Tokenization
* Cross Entropy
* Teacher Forcing
* Loss Mask
* Gradient Accumulation
* Mixed Precision
* Packing

这是日常训练离不开的知识。

---

### 第二层（Agent训练必须掌握）

* Long Context训练
* RoPE Scaling
* Sequence Parallelism
* Agent Trajectory SFT
* Tool Call Formatting
* Loss Weighting

因为这些直接决定 Agent 能否学会推理和工具使用。

---

### 第三层（研究人员级别）

* DPO
* PPO
* GRPO
* RFT
* Process Supervision
* Synthetic Data Generation
* Curriculum Learning

这是当前后训练（Post-training）领域最活跃的方向。

---

对于你目前的场景（长 Agent 轨迹、Qwen 系列、计划训练自己的 Agent 模型），真正值得深入研究的其实已经不是「普通 SFT」，而是：

> **长轨迹 Agent SFT 的梯度传播、Credit Assignment、Trajectory Packing、Observation Masking、Loss Reweighting 和后续 DPO/RFT 衔接。**

这些问题往往比模型结构本身更决定最终 Agent 能力。甚至很多 Agent 项目 80% 的效果差异，都来自数据与 SFT 设计，而不是底座模型。
